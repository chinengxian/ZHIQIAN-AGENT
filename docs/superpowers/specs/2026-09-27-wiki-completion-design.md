# Wiki 功能完善设计

- 日期：2026-09-27
- 状态：approved
- 关联需求：`docs/requirements/REQ-006.md`（AC-001～AC-010）
- 关联任务：`docs/tasks/TASK-031.md`
- 范围依据：用户要求使用 ZQ 流程完善 Wiki，并批准增量收口方案、现有 Wiki 页签深链方案、四层验证及人民币 5 元真实模型费用上限。

## 目标

在不引入 GraphRAG、新数据库或独立 Wiki 应用的前提下，把现有 Wiki 从“功能原型”完善为可浏览、可恢复、可追溯、可真实验收的知识库衍生能力：

1. 模型生成的结论逐条关联活动文档 chunk，无法校验的结论不得进入 Agent 可信结果。
2. 跨文档主题能够处理名称格式差异和明确别名，同时避免激进误合并。
3. 目录与正文以安全的可视化页面展示，内部链接可导航并支持页面深链。
4. 失败任务可由使用者恢复，发布重试不重复调用模型、计费或创建版本。
5. 以真实 PostgreSQL、Redis、Celery、浏览器和受控付费模型完成 REQ-006 验收。

## 非目标

- 不加入 GraphRAG、Neo4j、实体关系页、跨知识库 Wiki 或 Agent 写 Wiki。
- 不引入富文本编辑器、任意 HTML 渲染或新的长期运行服务。
- 不改变当前单工作区、无登录的产品边界；公开多用户部署前仍需另立权限需求。
- 不重做现有 Wiki 数据表；本轮优先复用 `generation_metadata`、任务 payload 和现有版本/来源表。

## 总体架构

沿用现有链路：

```text
活动文档版本
  → Outbox
  → Redis / Celery Wiki Worker
  → 额度预留
  → 结构化生成
  → claim 来源校验
  → 摘要页与主题归并
  → 目录重建
  → 发布或待审核
  → Vue Wiki 页签
  → Agent 只读可信 claim
```

同一知识库仍通过 `WikiConfig` 行锁串行发布。模型调用在事务外执行；页面、claim、来源、目录和任务状态在数据库事务内更新。已有 PostgreSQL 表继续作为权威状态，Milvus 不存储 Wiki 页面。

## 结构化生成与可信来源

### 生成协议

`WikiGeneration` 扩展为三个明确部分：

```json
{
  "summary": "文档摘要",
  "topics": [
    {"name": "离线操作", "aliases": ["离线运行"]}
  ],
  "claims": [
    {"text": "设备支持离线操作。", "source_indices": [1, 3]}
  ]
}
```

- `source_indices` 使用当前批次传给模型的、从 1 开始的稳定编号。
- 服务端校验类型、长度、数量、重复项和来源范围，不接受模型提供数据库 ID。
- 多批次文档先产生带来源编号的局部结果，再汇总摘要和主题；claim 保留原批次到真实 chunk 的映射，不允许汇总步骤伪造来源。
- 生成摘要可展示，但 Agent 只使用经过来源校验的 claim。

### 信任规则

- 所有来源编号存在、对应当前活动文档版本且内容哈希匹配时，claim 为 `verified`。
- 来源为空、越界、已失效或无法定位时，claim 为 `needs_review`，并记录稳定原因码。
- 页面正文可以展示待核实内容及状态；`wiki_search` 和 `wiki_read_page` 继续只返回 `verified` claim。
- 读取时仍实时检查文档状态、活动版本、chunk kind/ordinal 与内容哈希，覆盖异步失效窗口。

## 主题身份与跨文档归并

新增独立 `TopicResolver`，生成器只给候选名称和别名，不能直接指定页面 ID 或覆盖现有主题身份。

归并顺序：

1. 对名称和别名执行 Unicode NFKC、大小写、首尾空白、连续空白和常见标点规范化。
2. 与现有主题页 `generation_metadata` 中的规范名和别名精确匹配。
3. 对未命中的候选执行保守的字符/词片段相似度匹配；只有唯一候选超过固定阈值时合并。
4. 多个候选接近或相似度不足时创建独立主题，不依赖模型猜测身份。
5. 只有至少两个不同文档的当前摘要命中同一主题时才生成跨文档主题页。

主题页复制来源摘要版本的已校验 claim。来源变化后，旧主题页保留，但相应 claim 在读取时降为待核实，Agent 不再使用。

## 任务恢复与幂等

### Worker 失败边界

`WikiProcessor.run()` 分开处理：

- 生成失败：释放预留额度，按现有退避策略重试；达到上限后进入 `failed`。
- 发布失败：保留已经结算的生成检查点和用量记录，重试时直接从发布阶段继续，不再次调用模型。
- Worker 超时或退出：现有 stale recovery 重新投递同一任务；检查点和调用幂等键保持不变。

### 人工重试接口

新增：

```text
POST /api/v1/knowledge-bases/{knowledge_base_id}/wiki/jobs/{job_id}/retry
```

规则：

- 仅允许归属当前知识库的 `failed` 任务。
- Wiki 必须开启，知识库必须启用，来源版本必须仍为当前 ready 版本。
- 重置任务尝试窗口并重新入队同一任务；保留生成检查点和 Token 调用幂等键。
- 任务已经 pending/running/retry 时重复调用返回当前状态，不创建重复事件。
- 来源失效返回 409，知识库或任务不存在返回 404，Wiki 停用返回 409。

## 可视化页面

保留“知识库详情 → Wiki”作为唯一工作台，不建立独立 Wiki 应用。页面分为：

- 顶部：Wiki 开关、累计 Token 上限、已用/预留/可用量和刷新状态。
- 左侧：目录、跨文档主题、文档摘要三级分组导航。
- 中间：安全渲染的页面标题、段落、列表和内部链接。
- 来源区域：claim 状态、原文标题、版本、chunk、标题路径和页码。
- 任务区域：中文阶段、进度、错误原因及最终失败任务的重试操作。
- 版本区域：历史、双栏差异、审核、拒绝与回滚。

新增 `WikiContentRenderer`，只解析受控 Markdown 子集和 `[[slug|title]]`：

- 不使用未清洗的 `v-html`，不执行原文 HTML、脚本或事件属性。
- 内部链接按 slug 查找当前知识库页面并触发导航。
- 找不到目标时显示不可用状态，不跳到其他知识库。

路由支持页面深链：

```text
/knowledge/{knowledge_base_id}/wiki/{page_id}
```

刷新、前进后退和复制链接后仍打开同一页；非法或跨库 page ID 显示安全的 404/空状态。

## 刷新与交互状态

- Wiki 面板首次进入立即读取配置、页面和任务。
- 存在 pending、running、retry_wait、paused 状态时每 5 秒刷新；全部进入终态后停止。
- 切换知识库、切换路由或组件卸载时清理定时器，防止旧请求覆盖新页面。
- 编辑、审核、回滚和重试遇到 409 时提示状态已变化并重新加载。
- 失败信息只显示稳定错误码映射后的中文说明，不展示模型原始响应或内部异常。

## Token 与费用控制

- 继续以每知识库累计 `token_limit` 进行预留和结算。
- 新结构化输出、多批次汇总所需的最大输出 Token 必须计入预留估算。
- 供应商返回 usage 时记录实测 Token；未返回时按预留量保守计费并标记为估算。
- 真实模型验收总费用上限为人民币 5 元：调用前核对当前 provider、模型和可获得的公开价格，按最坏输入/输出量估算；无法证明低于上限时不发起付费调用。
- 真实验收只发送合成文档，不发送用户业务文档、凭据或既有知识库内容。

## 验证策略

### 单元测试

- 结构化生成：有效 JSON、代码块 JSON、非法结构、来源越界、重复来源、长内容截断。
- TopicResolver：Unicode/空白/标点、别名命中、唯一相似匹配、歧义拒绝、不同文档约束。
- Processor：生成失败、发布失败检查点、重复事件、Token 幂等、stale recovery。
- Service/API：人工重试成功、重复重试、停用、来源失效、跨库拒绝。
- Vue：安全渲染、内部导航、深链恢复、轮询启动/停止、错误状态和重试按钮。

### 真实基础设施集成

使用独立 PostgreSQL 测试库、Redis 和真实 Celery Worker，模型使用本地确定性兼容接口：

- 两个文档并发入队后形成摘要、共同主题和目录。
- 模型失败自动重试，最终失败可人工恢复。
- 发布阶段失败不会重复模型调用或 Token 入账。
- 文档更新/删除、Wiki 停用/重启、预算暂停/提升均保持幂等。

### 真实浏览器闭环

新增不拦截 Wiki API 的 `wiki.real.spec.ts`，在桌面和移动视口执行：

1. 创建测试知识库并上传合成文档。
2. 开启 Wiki 并等待真实 Worker 完成。
3. 从目录打开摘要和主题，展开来源并验证定位。
4. 编辑、审核、回滚并验证深链刷新。
5. 验证失败提示和人工重试。
6. 清理本测试创建的数据。

### 真实付费模型

在人民币 5 元上限内，用两篇短合成文档验证：

- 每篇摘要是否覆盖关键事实。
- 跨文档共同主题是否形成。
- verified claim 的来源是否真实支持结论。
- Agent 引用 `needs_review` 的次数必须为 0。
- 供应商 usage、Wiki 用量记录和 UI 展示是否一致；无 usage 时明确验证估算路径。
