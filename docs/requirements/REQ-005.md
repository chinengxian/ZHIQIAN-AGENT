# REQ-005 原生知识库与多级 RAG

- 修订：1
- 状态：confirmed
- 范围依据：用户于 2026-09-20 明确要求参考 Tencent/WeKnora 的做法，在当前项目内原生实现知识库检索，不调用 WeKnora；随后确认文档格式、PostgreSQL + Milvus + Redis、独立 Embedding、知识库页面、父子分块与混合检索，并批准正式技术设计。

## 目标与角色

单工作区使用者可以上传并管理 PDF、DOCX、Markdown 和 TXT 文档；系统异步解析、分块和索引后，现有 LangChain Agent 可以按会话知识范围自主检索，并在流式回答中提供可回溯来源。部署者可以独立配置聊天模型、Embedding 和可选 Reranker。

## 范围

- 范围内：知识库与文档管理、Docling 解析、父子分块、PostgreSQL 事实数据、Milvus Dense + BM25、Redis/Celery 异步任务、RRF 与可选 BGE Rerank、三个只读 Agent 工具、会话知识范围、引用 SSE、左侧知识工作台、任务恢复、安全边界、评测与全栈验收。
- 范围外：Wiki 生成与编辑、GraphRAG、多用户/RBAC、外部数据源同步、云对象存储、长期会话持久化、人工 chunk 编辑、病毒扫描实现和热迁移 Embedding 维度。

## 业务规则

1. PostgreSQL 是知识状态、正文、版本和引用的事实源；Milvus 只是可以从活动版本重建的检索索引。
2. 上传必须异步执行。API 在持久化文档、版本、任务和 outbox 后返回 202，不等待解析或 Embedding。
3. 只允许 PDF、DOCX、Markdown 和 TXT；默认单文件最大 50 MB，并同时校验扩展名、MIME、文件签名和受控存储路径。
4. Docling 负责统一解析；父块保留章节上下文，子块进入 Milvus，用于 Dense + BM25 精确命中。
5. 新文档版本只有在 PostgreSQL/Milvus 写入和完整性检查通过后才成为活动版本；失败时旧版本继续服务。
6. 默认混合检索使用 Dense、BM25、RRF；Cross-Encoder Reranker 是独立、可关闭的后处理策略。
7. Agent 只能调用 `search_knowledge`、`read_document`、`list_documents` 三个只读工具，不得通过工具上传、删除或修改知识。
8. 默认检索全部启用知识库；用户可以为当前会话选择一个或多个知识库缩小范围。
9. 无有效命中或检索不可用时必须明确降级，不能生成虚假引用。
10. 首版使用固定单工作区且无登录；领域数据仍保存 `workspace_id`，不得把 conversation ID 当作安全凭证。
11. Wiki 是后续衍生知识阶段，必须另行完成需求、设计和计划后才能实施。
