# REQ-006 知识库内 Wiki 衍生知识

- 修订：8
- 状态：confirmed
- 范围依据：用户于 2026-09-22 要求参考 WeKnora 讨论下一阶段 Wiki，逐项确认业务规则，并回复“按此规格实施”批准本需求、技术设计与实施计划。

## 目标与角色

单工作区使用者希望把一个知识库中的原始文档整理成可按主题浏览、能追溯原文的 Wiki。使用者可以检查生成结果，维护页面，并在来源变化时识别过时内容。现有 Agent 后续可以只读 Wiki，再回到原文核实引用。

## 范围

- 已确认范围：一个源知识库对应其自身的 Wiki；Wiki 是现有 RAG 上的衍生知识层，不替代原文档和检索索引。
- 已确认的首版页面：每篇文档摘要、跨文档主题页和目录索引；按知识库手动开启后异步生成，并提供来源引用、人工编辑、版本历史、diff、回滚与来源变化提示。
- 建议后续：独立实体页、跨知识库 Wiki、Agent 自动改写、GraphRAG、复杂问题自动归档为页面。上述均未获本轮确认。

## 业务规则

1. Wiki 页面归属现有知识库。技术设计建议沿用现有知识库 ID 作为归属，不新建独立的 Wiki 知识库类型。页面可以引用同一知识库的文档版本和 chunk；跨知识库来源不在首版候选范围。
2. Wiki 按知识库手动开启；开启时纳入该库已有文档，此后在文档就绪后自动增量处理。未开启的知识库不生成 Wiki。
3. 页面内容与来源的可追溯性必须在设计中定义到具体文档版本和 chunk；仅记录文件名不足以判定原文更新后的有效性。
4. 人工修改过的页面遇到原文增量更新时，保留当前已发布版本，生成待审核更新和差异；经使用者确认后才发布。
5. 原文更新或删除使引用失效时，保留页面并标记受影响结论为“待核实”；核实完成前，Agent 不得将这些结论作为可信引用。
6. 首版自动生成每篇活动文档的摘要、跨文档主题页和该知识库的目录索引。主题页中的综合结论必须能分别追溯到支持它的原文证据。
7. 每个知识库设置累计 Wiki 生成 token 上限，不自动重置；页面展示预计与实际 token 用量。达到上限后暂停尚未执行的生成任务，使用者提高上限后可继续。调用中用量统计与超限处理需在设计中明确。
8. 回滚创建新的已发布版本，并视为人工修改。后续原文更新仍可生成待审核更新，但不得自动覆盖回滚后的页面。
9. 关闭 Wiki 后，已发布页面保留并可供使用者浏览；停止新的生成任务，Agent 不再使用该知识库的 Wiki。重新开启后先检查来源版本和引用有效性，再恢复增量处理。

## 事实与假设

- 已观察技术事实：`src/agent_api/knowledge/infrastructure/database/models.py` 中已有 `KnowledgeBase`、`Document.active_version_id`、`DocumentVersion`、`Chunk` 和 `OutboxEvent`；`src/agent_api/knowledge/worker/cleanup.py` 中单篇文档删除保留数据库版本记录但移除索引和原文件，整个知识库删除则删除其数据库记录；`docs/verification/VERIFY-004.md` 记录 REQ-005 的真实 API/Worker 与浏览器验收。
- 用户提供的业务事实：每个知识库一个 Wiki；手动开启后先处理既有文档，之后自动增量；首版生成文档摘要、跨文档主题页和目录索引；每库设置累计 token 上限、不自动重置、超限暂停；人工编辑和回滚后的自动更新均待审核；来源失效时保留页面、标记待核实并排除可信引用；关闭 Wiki 后保留页面供浏览，停止生成和 Agent 使用。此前 REQ-005 确认 Wiki 应另立阶段，参考 WeKnora 而不调用其服务。
- 外部参考事实：[WeKnora Wiki 文档](https://github.com/Tencent/WeKnora/blob/main/website-docs/03-features/14-wiki.md) 描述知识库内异步生成、分块引用、页面编辑与版本回滚；[早期提案](https://github.com/Tencent/WeKnora/issues/919) 的独立 Wiki 库绑定方案属于提案，不作为现行实现或本项目既定需求。
- 待确认假设：技术上建议只处理 ready 活动版本，在活动版本切换成功后触发增量；该触发点需在架构设计中验证。
