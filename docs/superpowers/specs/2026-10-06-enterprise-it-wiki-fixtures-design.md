生成 8 篇相互独立、主题交叉的 Markdown 语料文档，并附文档索引和测试问题清单，共 10 个 Markdown 文件。语料使用虚构企业背景，不包含真实人员、地址、账号、密钥或业务数据。

测试重点包括：

1. 同一主题在不同文档中的重复表达与同义词归并。
2. 新旧规则、生效日期和替代关系的正确识别。
3. 总则与专项规则、普通资产与高风险资产之间的适用范围判断。
4. 跨文档操作链路和多跳问题的综合回答。
5. Wiki 结论到原始文档的引用追溯。
6. 唯一事实不被错误扩展到其他主题或适用对象。

## 统一文档结构

每篇语料文档使用一致的头部元数据和正文结构：

```yaml
---
document_id: IT-OPS-XXX
title: 文档标题
version: 版本号
effective_date: YYYY-MM-DD
status: effective 或 superseded
scope: 适用范围
owner: 责任部门
supersedes: 被替代文档或条款
tags: [主题标签]
---
```

正文包含目的、适用范围、术语、规则、操作步骤、升级路径、例外和相关主题。相关主题同时使用自然语言与 `[[主题名称]]` Wiki 链接，分别支持隐式和显式主题识别测试。

## 主题交叉设计

### 同义词与别名

- `MFA`、`多因素认证`、`双因素校验`
- `P1`、`一级事件`、`严重事件`
- `补丁窗口`、`维护窗口`、`变更窗口`
- `灾难恢复`、`DR`、`业务恢复`
- `账号泄露`、`凭据泄露`、`身份失陷`

别名会分散在不同文档中，避免所有文档都直接给出完整映射，使系统需要进行主题归并。

### 重复事实

以下事实会由多个文档从不同角度说明：

- 远程访问必须使用 MFA。
- P1 事件需要立即升级并启动事件响应。
- 发现凭据泄露后需要禁用或重置账号，并撤销活动会话。
- 严重漏洞需要在规定时限内修复或获得例外批准。
- 灾难恢复演练必须记录恢复结果并复核 RPO/RTO。

### 范围差异

- 普通办公终端与互联网暴露资产使用不同的漏洞修复时限。
- 普通账号与特权账号使用不同的认证和会话要求。
- 生产系统与非生产系统使用不同的恢复目标。
- 总部员工、分支机构员工和第三方供应商使用不同的 VPN 接入要求。

这些差异必须在相关段落中明确适用对象，避免形成无法解释的真实矛盾。

### 时间冲突与替代关系

第 8 篇变更公告于 2026-07-01 生效，并明确替代部分旧规则：

- 普通员工密码从“每 90 天强制更换”调整为“无固定轮换周期；检测到泄露、弱口令或风险事件时强制更换”。
- 严重漏洞的通用修复时限仍为 72 小时，但互联网暴露资产调整为 24 小时。
- VPN 从“密码加短信验证码”升级为“抗钓鱼 MFA 优先；不支持时使用经批准的过渡方案”。

旧规则仍保留在历史文档中并标注原生效范围，使测试系统必须结合状态、生效日期和适用范围得出当前结论。

## 跨文档链路

语料支持以下多跳路径：

```text
监控发现异常
  → 按告警制度判断为 P1
  → 启动安全事件响应
  → 隔离终端并撤销账号会话
  → 按访问规范恢复身份
  → 按补丁规范完成修复
  → 按备份手册校验恢复点
```

设备丢失、账号泄露、勒索软件和严重漏洞四类场景均至少跨越三篇文档，适合验证 Wiki 主题页的来源聚合和 Agent 多文档回答。

## 测试问题设计

`TEST-QUESTIONS.md` 至少覆盖以下类型：

1. 单文档精确事实题。
2. 同主题多文档归纳题。
3. 别名识别题。
4. 生效日期与新旧规则判断题。
5. 适用范围与条件差异题。
6. 三篇以上文档参与的多跳处置题。
7. 不足信息题，期望系统明确无法确定而不是编造。

每道题记录问题、预期要点、预期引用文档和常见错误。测试清单不写入语料知识库，以免答案泄漏；导入时仅导入编号 01～08 的语料文档。

## 验收标准

- 目录内存在 8 篇语料、1 篇索引和 1 篇测试清单。
- 所有 Markdown 文件可独立阅读，内部相对链接有效。
- 每个核心主题至少出现在两篇文档中。
- 至少三组规则包含可通过日期、范围或优先级消解的表面冲突。
- 至少四道问题需要组合三篇或更多文档才能完整回答。
- 每篇文档至少包含一个唯一事实，用于检测错误泛化。
- 测试清单明确区分“预期引用”和“不可作为答案来源的测试说明”。
- 不含真实秘密、个人信息、外部依赖或需要联网验证的事实。

3. Markdown 相对链接目标检查。
4. 核心主题跨文档出现次数检查。

6. 敏感信息与占位符扫描。
