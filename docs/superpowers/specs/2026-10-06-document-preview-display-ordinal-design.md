# 文档预览连续段号设计

## 背景

知识库采用父子分块。父块和子块共享文档版本内的原始 `ordinal` 序列，正文预览只返回父块，因此界面会显示为“第 0、2、4 段”等不连续编号。缺失编号对应子块，正文并未丢失，但当前文案容易让用户误解。

## 目标

- 正文预览按父块顺序显示“第 1、2、3 段”。
- 翻页加载和从引用定位到文档中间时，展示编号仍是文档内的全局稳定编号。
- 保留原始 `ordinal`，不改变父子块关联、向量检索、来源定位和 Wiki 引用语义。
- 不迁移数据库，不要求重新上传或重新索引文档。

## 方案

后端预览响应为每个父块增加一基的 `display_ordinal`。该值是在同一文档版本的父块集合中，按 `(ordinal, id)` 排序后的稳定排名。游标筛选和锚点定位发生后，返回项仍携带其全局排名，不能从当前页面重新计数。

前端 `DocumentPreviewChunk` 类型增加 `display_ordinal`，正文卡片使用它生成“第 N 段”文案。原始 `ordinal` 继续保留在接口结构中，供兼容和内部定位使用，但不再直接作为用户可见段号。

## 数据流

1. 预览服务确定目标文档版本。
2. 服务只对 `parent_chunk_id IS NULL` 的父块按 `(ordinal, id)` 建立一基排名。
3. 服务应用现有游标或锚点条件并分页，返回 `ordinal` 与 `display_ordinal`。
4. 前端显示 `display_ordinal`，追加下一页时无需自行推算偏移量。

## 兼容性与错误处理

- 数据库模型和已有分块数据保持不变。
- 预览分页游标继续基于原始 `(ordinal, id)`，避免改变已有游标语义。
- 来源锚点仍通过原始块 ID 定位；若锚点是子块，继续回到其父块，再返回该父块的全局展示序号。
- 空预览和失效来源沿用现有响应，不产生虚假的展示编号。

## 测试

- 后端集成测试覆盖父块原始序号不连续时，`display_ordinal` 从 1 连续递增。
- 后端测试覆盖第二页仍返回全局编号，而不是重新从 1 开始。
- 后端测试覆盖从子块锚点定位父块时返回正确的全局编号。
- 前端测试覆盖页面使用 `display_ordinal` 渲染“第 N 段”，不再直接展示原始 `ordinal`。

## 非目标

- 不修改父子分块算法。
- 不重新编号数据库中的 `chunks.ordinal`。
- 不改变 Milvus 索引、检索排序或 Wiki 引用格式。
