# Wiki 聚合页可读化设计

## 目标

在不增加模型调用、不改变已有文档摘要生成链路的前提下，将 Wiki 首页和主题页从原始 Markdown 目录、跨文档事实清单，升级为可直接阅读且可追溯来源的聚合页面。

本期同时让已修复的主题别名去重逻辑在 Celery worker 中生效，避免后续文档的 Wiki 发布在主题聚合阶段停止。

## 非目标

- 不建立独立 Wiki 向量索引，不改变现有搜索排序；该项属于 Route C。
- 不调用模型生成跨文档综述，不新增 token 预算或审核流程。
- 不修改文档摘要页的 `wiki-v2` 生成协议。
- 不改变人工编辑、审核、回滚与来源有效性校验规则。

## 现状与问题

文档摘要页已使用 `summary_section` 形成可读段落并保留 chunk 引用。但主题页只把相关 `summary_fact` 按文档拼接为 Markdown 列表，首页也仅为链接目录。用户无法先理解主题结论，且大量事实默认展开会掩盖重点。

主题归属存在多个等价别名时，同一摘要事实可能重复进入主题页；该问题已通过按源结论 ID 去重修复，尚需重新启动 worker 使常驻进程加载该修复。

## 页面体验

### 首页

首页显示以下确定性导航信息：

- 知识库内的主题数与文档摘要数；
- 主题入口，按主题标题排序；
- 文档摘要入口，按摘要标题排序。

首页不承担事实陈述，因此不需要模型摘要或来源 claim。它在前端由已加载的页面列表渲染为导航卡，而不是把 `index/home` 的 Markdown 目录原样展示。

### 主题页

主题页采用“结论优先”布局：

1. 顶部显示主题标题、别名、涉及文档数和已核实事实数。
2. 默认展示相关文档的可读摘要段落，标题格式为“文档标题 · 段落标题”。
3. 每个段落可展开其原始 chunk 来源；没有可验证来源的段落不得标记为已核实。
4. 原子事实保留在默认收起的“全部已核实事实”区域，用户按需查看和定位来源。
5. 所有涉及文档显示为可跳转至其摘要页的入口。

## 后端数据流

1. `_rebuild_topic_pages` 保持以主题 source chunk 识别相关内容的规则。
2. 对每个命中主题的摘要页，查询其 `summary_section` claim 及来源；只有来源 chunk 与主题 source chunk 交集非空的摘要段落才能进入主题可读段落。
3. 以源 `summary_section` claim ID 去重，避免同一文档通过等价别名重复写入。
4. 主题页写入两类 claim：
   - `summary_section`：复用原摘要段落文本和精确来源，用于默认阅读；
   - `topic_fact`：保留原子事实和精确来源，用于可折叠的完整证据层。
5. `generation_metadata.summary_sections` 记录主题段落标题；现有 API 的 `summary_sections` 响应继续复用，避免新增表或破坏文档摘要契约。
6. 新增无模型的聚合页重建入口，仅基于当前已发布的摘要页重建 topic 与 `index/home`。该入口不得创建或重新执行文档 Wiki 生成任务。

## 前端数据流

- `WikiPanel` 对 `index` 页面按已加载的 `pages` 集合渲染主题与摘要导航卡。
- `WikiPanel` 对 `topic` 页面复用已有 `summary_sections` 和来源展开组件渲染可读段落。
- `topic_fact` 渲染在原生 `details` 折叠区；进入该区域后仍保留现有高亮、有效性状态和来源跳转。
- 非 pipeline、人工编辑或回滚版本继续按现有正文和 claim 展示，防止覆盖人工内容。

## 运行与恢复

- 先完成代码测试与静态检查，再重启当前 Celery worker；不主动中断仍在运行的 Wiki job。
- 对现有知识库执行一次聚合页重建，不调用模型、不扣除 token。
- 若聚合页发布失败，事务必须回滚，现有已发布版本继续可读；系统不应留下部分 claim 或重复来源。

## 验收标准

- 首页不再以预格式化 Markdown 目录作为默认阅读内容。
- 主题页默认显示来源充分的摘要段落，而非完整原子事实清单。
- 每个主题段落可查看有效的 chunk 来源并跳转到文档摘要。
- “全部已核实事实”默认收起，数量与当前主题 claim 一致。
- 现有 8 个 `wiki-v2` 文档摘要无需重新生成即可完成聚合页重建。
- 重复主题别名不会导致同一 `topic_fact` 或主题摘要段落重复写入。
- 重建过程不产生 `WikiTokenUsage` 记录，也不增加 `tokens_charged`。
