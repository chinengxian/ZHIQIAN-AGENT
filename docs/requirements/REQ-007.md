# REQ-007 文档详情与正文预览

- 修订：1
- 状态：confirmed
- 范围依据：用户于 2026-10-05 指出知识库与 Wiki 已完成上传和生成，但前端无法查看文档等信息，并明确要求增加该功能。

## 目标与角色

单工作区使用者可以从知识库文档列表查看上传文档的详细信息和已解析正文，也可以从 Wiki 引用直接定位到对应文档版本与分块，而不需要接触数据库、磁盘路径或内部管理工具。

## 范围

- 在现有知识库工作台内提供文档详情深链，不新增独立应用或第二套导航。
- 展示文档名称、文件名、格式、处理状态、活动版本、文件大小、版本时间、最近任务阶段及用户安全的失败信息。
- 对已解析且仍保有分块的文档版本提供分页正文预览，展示标题路径、页码或分块顺序；正文按纯文本安全渲染。
- 文档列表项可进入详情；Wiki 来源可进入相同详情，并定位到其 `document_version_id` 与 `chunk_id` 对应的正文位置。
- 桌面端与移动端都要支持加载、空内容、处理中、失败、来源失效和资源不存在状态。

## 业务规则

1. 默认展示活动版本；从 Wiki 引用进入时优先展示引用指定的文档版本，不得静默切换为当前活动版本。
2. Wiki 的 `chunk_id` 若指向子块，预览应定位到其父块上下文并标记具体命中范围；找不到正文时仍展示来源元数据和明确的“正文不可用”状态。
3. 只有属于目标文档的版本和分块可以被读取；跨文档、跨知识库或不存在的标识统一安全拒绝。
4. 正文预览必须分页并限制单页条数与响应体积，不能一次返回整篇大文档。
5. 浏览器不得获得原文件磁盘路径、内容哈希、Embedding 配置、内部异常堆栈或模型密钥。
6. 页面只渲染纯文本和受控定位信息，不执行文档中的 HTML、脚本、事件属性或外部资源。
7. `pending`、`processing`、`failed`、`deleting` 文档仍可查看已有元数据；没有可预览版本时给出与状态一致的说明，不伪装为空白成功。

## 非目标

- 原文件下载、PDF/Office 原生嵌入式阅读器。
- 在线编辑文档正文、人工编辑 chunk、回滚或恢复原文档版本。
- 新增文档解析格式、OCR 能力或上传流程。
- 新增多用户权限模型；继续沿用当前固定工作区归属检查。

## 关联与变更

- 本需求扩展 REQ-005 的知识库管理可视性，以及 REQ-006 的 Wiki 来源定位体验；不改变现有上传、检索、Wiki 生成与 Agent 引用语义。
- 现有 `GET /api/v1/documents/{document_id}` 只返回列表同级状态字段，前端文档行也没有详情入口；Wiki 来源按钮目前只展开版本与 chunk 标识。这些是本需求的现状依据。
- 沿用已确认的知识库工作台视觉基线；本次属于现有页面内的详情与响应式状态完善，不触发新的视觉确认门槛。
